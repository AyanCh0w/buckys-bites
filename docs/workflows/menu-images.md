# SCU menu images

Run this workflow when asked to fetch an SCU menu and fill in missing food images. Use the requested campus date in America/Los_Angeles. Default to Marketplace, as in the existing dish and component lists. Expand to other cafés when requested. Run through image generation and verification unless the request is for prompts only.

## Fetch and prepare

1. From the project root, run `python3 "scripts/menu/fetch_scu_menu.py" --date YYYY-MM-DD --cafe marketplace-2`. Use the nutrition workflow for bulk date and café options. Confirm the requested snapshot succeeded before using its records. Read the snapshot under `data/menu/scu-catalog/snapshots/`. Keep the source records intact.
2. Extract named assembled dishes and their food components. Include prepared breakfast plates, composed salads and soups. Keep sides as components of the dishes that include them. Exclude standalone ingredients, toppings, sides, drinks and desserts from the main dish list. Use recipe entries and descriptions to identify meaningful components. For a recipe listed as one entry, use its published ingredients and description to summarize the visible components without breaking them into individual seasonings or subingredients. Preserve published conflicts in the underlying data. Use a generic component name when needed rather than choosing between conflicting details. Keep dates and origin in the data. Leave times and opening hours out of the display.
3. Produce two alphabetical lists, one for dish names and one for dish components. Use case, spacing and punctuation normalization and an explicit alias table for equivalent names, such as “mozzarella cheese” and “mozzarella.” Retain genuinely different foods, preparations, portions and sides. Preserve choices as distinct component options. Reruns must preserve existing keys when a name is reworded. Keep dish and component identities separate because their framing is different.

## Check what already exists

4. Check the existing asset inventory, any image folders already used by the project, and `data/menu/scu-images/`. Maintain `data/menu/scu-images/manifest.json` across runs. Use a stable key for each distinct dish or component, with separate `dish` and `component` namespaces. Store the display name, aliases, type, food and sides, source references, prompt, generator settings, output path and status. Match by key, known alias and artwork content before creating a new entry. If two names share a base but depict meaningfully different food or portions, keep separate keys. Reuse a compatible, verified image even when it came from an earlier date.
5. Save verified existing entries as `ready`. Mark entries with no confirmed usable PNG as `missing`, and record anything that needs review. A prompt or an output filename on its own does not count as a completed image. Review against any supplied app asset conventions before creating a parallel asset path. Never replace a usable image unless requested.

## Write prompts and generate missing images

6. Write or reuse a complete prompt for each missing entry. The prior batch is in `data/menu/scu-menu-2026-11-18-image-prompts.json`. Use it when it matches the current food and portion. Open with the complete list of visible food, including listed sides and specific counts, cuts and textures. Explicitly exclude unlisted foods, sauces, toppings and garnish. When there is no side, direct the generator to leave the remaining bowl space empty. Name likely unwanted additions for each dish, such as toast for plain eggs or syrup for plain pancakes. For menu choices, select one representative version and record which. For standalone thin liquids, specify a small, bounded pool with no container or stray droplets. If a liquid comes with a main dish and needs a vessel, use a small plain serving cup inside the bowl. Keep the entire bowl and food in frame.
7. Call the image generator for each missing entry with its prompt and **`transparent_background: true`**. Request a square PNG. Generate one isolated asset per prompt. For large queues, process in batches and save progress after each asset so a rerun can resume. Use `data/menu/scu-images/dishes/<key>.png` and `data/menu/scu-images/components/<key>.png` unless the project already has an asset location. Use the original generator file when available.
8. Open each result to verify framing, food count, visual match, believable textures, and the presence or absence of a bowl. Inspect PNG alpha values to check that corners are transparent, the subject is visible, and the contact shadow fades through partial alpha. A visible checkerboard embedded in the image is a failure. Save only verified images as `ready`; record failures, retry with a focused prompt adjustment, and leave unfinished items marked for the next run. Report counts for existing, created, and still missing images and link the lists, prompt file and manifest.

## Main dish prompt

> Photorealistic overhead menu photograph. Show only **[VISIBLE FOOD WITH SERVING COUNTS, CUTS, AND TEXTURES]**. **[KEEP LISTED SIDES IN DISTINCT PORTIONS OR LEAVE REMAINING BOWL SPACE EMPTY]**. Do not add unlisted food, sides, sauces, toppings, or garnish. **[EXCLUDE TYPICAL UNWANTED ADDITIONS FOR THIS DISH]**. Use one perfectly round, shallow, matte warm-ivory ceramic bowl with a narrow smooth rim. Shoot straight down at 90 degrees. Center the bowl at about 78% of the square canvas width. Show the entire rim with even margins. Use soft, diffused studio light from the upper left, natural colors, and realistic textures. Export a square PNG with true alpha. Keep only the bowl, its contents, and a short soft contact shadow that fades into transparency. No text, logos, hands, utensils, props, surfaces, solid-color background, or checkerboard.

Generator setting `transparent_background: true`.

## Dish component prompt

> Photorealistic overhead ingredient cutout. Show only **[INGREDIENT OR PREPARED COMPONENT WITH COUNT, CUT, AND TEXTURE]**. Keep the pieces or dollops together as one compact portion. No bowl, plate, or container. Do not add ingredients, sides, toppings, or garnish beyond those explicitly described. Shoot straight down at 90 degrees. Center the entire portion at about 65% of the square canvas width with generous even margins. Keep the silhouette easy to read at thumbnail size. Use soft, diffused studio light from the upper left, natural colors, and realistic textures. Export a square PNG with true alpha. Keep only the food and a short soft contact shadow that fades into transparency. No text, logos, hands, utensils, props, surfaces, solid-color background, or checkerboard.

Generator setting `transparent_background: true`.
